VERSATECH OS — RÈGLES MÉTIER

BR-001 Une entreprise n'est jamais copiée pour devenir client. Son lifecycle évolue.
BR-002 Une opportunité commerciale appartient à une Company.
BR-003 Une Company peut avoir plusieurs opportunités dans le temps.
BR-004 Un passage en WON doit conserver l'historique et permettre de créer un Project.
BR-005 Un passage en LOST exige idéalement une raison de perte.
BR-006 Toute interaction importante doit avoir occurredAt.
BR-007 Une relance terminée conserve completedAt.
BR-008 Les KPI sont calculés depuis les données persistées.
BR-009 Un score prospect automatisé doit être explicable.
BR-010 Un devis envoyé peut générer une relance, mais l'automatisation doit être configurable.
BR-011 Un événement calendrier lié ne remplace pas l'objet métier.
BR-012 Une suppression de données historiques doit être exceptionnelle ; privilégier archive.
BR-013 GitHub est en lecture seule dans les premières versions.
BR-014 Les données externes ont un lastSyncedAt lorsqu'elles sont mises en cache.
BR-015 L'IA ne valide pas seule un paiement, une suppression, un changement critique ou un envoi externe.
BR-016 Le MRR correspond aux contrats de maintenance actifs récurrents.
BR-017 Pipeline brut = somme des opportunités ouvertes ; pipeline pondéré = somme valeur x probabilité.
BR-018 Un client peut avoir plusieurs projets.
BR-019 Un projet peut être en WAITING_CLIENT sans être considéré abandonné.
BR-020 Les notes de contact doivent être séparées des logs techniques.
