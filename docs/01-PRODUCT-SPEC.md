VERSATECH OS — PRODUCT SPECIFICATION

1. VISION
Créer un système d'exploitation interne pour VersaTech permettant de piloter l'activité depuis une interface unique, avec une vision immédiate de ce qui doit être fait aujourd'hui, de l'état commercial, des projets en cours et de la santé de l'entreprise.

2. PROBLÈMES À RÉSOUDRE
- Informations dispersées entre notes, appels, e-mails, GitHub, calendrier, devis et fichiers.
- Risque d'oublier une relance ou une échéance.
- Difficulté à mesurer l'efficacité de la prospection.
- Manque d'historique centralisé des décisions et contacts clients.
- Manque de vue consolidée sur pipeline, CA, MRR et charge projet.
- Besoin de relier activité commerciale et exécution technique.

3. UTILISATEURS
V1 : Marius, administrateur unique.
Architecture : prévoir qu'un futur collaborateur puisse avoir un compte et des permissions sans imposer le multi-utilisateur dans le MVP.

4. OBJECTIFS PRODUIT
- Afficher les priorités du jour.
- Centraliser chaque entreprise et son historique.
- Organiser la prospection et les relances.
- Transformer une opportunité gagnée en client/projet sans duplication.
- Suivre tâches, échéances et progression des projets.
- Afficher l'activité GitHub liée aux projets.
- Centraliser les références de documents.
- Suivre les principaux indicateurs commerciaux et financiers.
- Constituer une base de données exploitable pour les analytics et l'IA.

5. WORKFLOW COMMERCIAL PRINCIPAL
Identification -> Qualification -> À contacter -> Contacté -> Intéressé -> RDV -> Proposition/Devis -> Gagné ou Perdu.

Une entreprise reste la même entité pendant tout son cycle de vie.

6. WORKFLOW CLIENT
Gagné -> Client actif -> Projet créé -> Cadrage -> Production -> Validation -> Livraison -> Maintenance éventuelle -> Archivé.

7. MVP
Le MVP doit contenir :
- authentification ;
- dashboard Aujourd'hui ;
- entreprises ;
- contacts ;
- qualification ;
- activités/appels/notes ;
- relances ;
- opportunités ;
- pipeline Kanban ;
- tâches ;
- premiers KPI.

8. APRÈS MVP
- projets et milestones ;
- calendrier métier ;
- synchronisation calendrier externe ;
- GitHub ;
- documents ;
- devis/paiements/maintenance ;
- analytics avancés ;
- automatisations ;
- assistant IA.

9. HORS SCOPE INITIAL
- ERP comptable complet ;
- remplacement de Shine ou d'un logiciel comptable ;
- messagerie complète intégrée ;
- stockage de secrets GitHub dans les données métier ;
- génération autonome de décisions commerciales ;
- application mobile native.

10. CRITÈRES DE SUCCÈS
- Utilisable quotidiennement.
- Une relance importante ne doit plus dépendre de la mémoire.
- Toute entreprise doit disposer d'un historique compréhensible.
- Les KPI doivent provenir des données réelles, jamais de valeurs codées en dur.
- Les principales actions doivent demander peu de clics.
- L'application doit rester rapide même avec plusieurs années d'historique.

11. PRINCIPES PRODUIT
- Saisie rapide.
- Historique plutôt que remplacement silencieux des informations importantes.
- Donnée structurée avant IA.
- Automatisation progressive.
- Une seule source de vérité par concept.
- Les intégrations externes enrichissent VersaTech OS ; elles ne doivent pas devenir son modèle métier.
